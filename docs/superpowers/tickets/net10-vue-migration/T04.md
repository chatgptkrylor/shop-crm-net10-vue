## Acceptance criteria

- `GET /api/customers?page=N` returns `200 PagedResult<CustomerDto>` with `items, page, pageSize, totalPages, totalCount` (page size 10, 1-indexed).
- `POST /api/customers` with a valid `CustomerDto` returns `201 CustomerDto`; invalid returns `400 ValidationProblemDetails` with field-keyed `errors`.
- `GET /api/customers/{id}` returns `200 { customer, interactions }` (interactions embedded) or `404`.
- `PUT /api/customers/{id}` returns `200 CustomerDto` or `404`; `DELETE /api/customers/{id}` returns `204` or `404`.
- `CustomerDto` validation mirrors the old `CustomerViewModel` annotations (Required Name/Status, StringLength(100) Name/Email/Company, StringLength(30) Phone, EmailAddress Email).
- `CustomersController` is `[Authorize]`; `CreatedByUserId` comes from the JWT `userId` claim.
- The Vue `CustomersIndexView` renders an `el-table` (Name, Email, Phone, Company, Status) with `el-pagination` bound to the store; "Create" button routes to `/customers/create`; row click routes to `/customers/:id`.
- `CustomerCreateView` and `CustomerEditView` render Element Plus forms with rules mirroring the annotations; on submit they call `customersStore.create()/update()` and redirect to `/customers`; server `ValidationProblemDetails.errors` are mapped to form fields.
- `customersStore` exposes `list, pagination, current, fetchAll, fetchOne, create, update, remove`.
- `CustomersTests` xUnit passes (list, create, get, update, delete, validation failure). `smoke-crud.sh` customer assertions pass. Playwright `customers.spec.ts` screenshots the table, creates a customer (row appears), edits it (changes persist), and deletes it (row gone).
