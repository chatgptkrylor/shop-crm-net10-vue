## Acceptance criteria

- `POST /api/account/login` with valid `admin` / `Admin@123` returns `200 { username, role }` and sets the `shopcrm_token` httpOnly cookie (SameSite=Strict, 20-min expiry). Invalid credentials return `401` with a generic "Invalid username or password" ProblemDetails.
- `POST /api/account/logout` clears the cookie and returns `204`.
- `GET /api/account/me` returns `200 { userId, username, role }` with a valid cookie, `401` without.
- All controllers except `AccountController.login` are `[Authorize]`; JWT bearer reads the token from the `shopcrm_token` cookie.
- The `X-Requested-With: XMLHttpRequest` header is required on all mutating endpoints; requests missing it return `400`.
- `IDbConnectionFactory` is injectable; `UserRepository` verifies passwords with `BCrypt.Net-Next` (latest) and the existing seed hash verifies.
- The Vue `LoginView` renders an Element Plus form with username/password fields and validation rules (Required). Successful login redirects to `/dashboard` (or `?redirect=`); failed login shows the API error.
- `authStore` exposes `user`, `role`, `isAuthenticated`, `login`, `logout`, `fetchMe`; `main.ts` hydrates it on boot via `GET /api/account/me`.
- The Vue Router `beforeEach` guard redirects unauthenticated users to `/login?redirect=...`.
- The shared Axios client sends `withCredentials: true` and `X-Requested-With: XMLHttpRequest`; a 401 interceptor clears `authStore` and redirects to `/login`.
- `LoginTests` and `AuthTests` xUnit tests pass. `smoke-auth.sh` exits 0. The Playwright `login.spec.ts` captures a screenshot of the login form, a successful login redirect, and a bad-password error.
